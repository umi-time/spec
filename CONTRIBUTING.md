# Contributing to the Umi‑Time Standard

Thank you for your interest in improving the Umi‑Time Standard.  
This repository contains the formal specification, published under **CC‑BY‑4.0**.

---

## Discussions

This repository is the **only** Umi‑Time repository with GitHub Discussions enabled.

Use Discussions when you want to:
- Ask questions about the standard  
- Propose conceptual or structural changes  
- Explore design considerations  
- Request clarification on definitions or algorithms  

If your topic is exploratory or conceptual, start with a Discussion.  
If your proposal is concrete and ready for review, open an Issue instead.

---

## Types of Contributions

You may contribute by:
- Proposing clarifications or corrections  
- Suggesting improvements to definitions or algorithms  
- Reporting inconsistencies or ambiguities  
- Contributing diagrams or explanatory material  
- Improving readability and structure  

All changes must preserve the intent and rigor of the standard.

---

## Workflow

### 1. Open an Issue
Before submitting a pull request, please open an issue describing:
- The section of the spec affected  
- The problem or ambiguity  
- Proposed resolution  
- Any supporting examples or references  

### 2. Submit a Pull Request
Pull requests should:
- Modify only the relevant sections  
- Include clear rationale in the PR description  
- Maintain consistent terminology  
- Preserve formatting conventions  
- Avoid introducing implementation‑specific details  

The spec is normative; implementation notes belong in other repos.

---

## Style Guidelines

- Use precise, unambiguous language  
- Define all terms before use  
- Express mathematical concepts and algorithms abstractly (avoid language-specific paradigms or syntax)
- Keep examples minimal and illustrative  
- Avoid referencing specific programming languages  
- Use consistent units and notation  
- Follow existing section structure and numbering
